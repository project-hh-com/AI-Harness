9-Agent Pipeline 6-Gate QA Impact Radius Check Framework-Agnostic

개요

AI-Harness는 Claude Code 위에서 동작하는 멀티 에이전트 개발 파이프라인입니다. 사용자가 자연어로 작업을 입력하면 9개의 전문화된 에이전트가 순서대로 실행되어 기획 → 구현 → QA → PR 생성까지 자동으로 처리합니다.

왜 AI-Harness인가

🎯

단일 명령

/implement 한 줄로 전체 파이프라인 실행

🔒

6단계 QA 게이트

Lint → Type → Pattern → TDAD → Complexity → Impact Radius

📡

변경 모듈을 import하는 모든 파일까지 무한호출·캐시충돌 탐지

9개 에이전트 흐름

각 에이전트를 클릭하면 상세 역할을 확인할 수 있습니다.

0
input-refiner
자연어 input → 표준 YAML input 정제 + project_type 감지
Agent 0
  • 자연어 input의 모호한 표현을 구조화된 YAML로 변환
  • project_type 자동 감지 (package.json / go.mod / Cargo.toml 등)
  • confidence < medium이면 사용자에게 명확화 질문 제시
  • 출력: .claude/refined-inputs/<task>.md
1
planner (Opus)
11 steps 분석 → 영향 파일 · 분기 매트릭스 · Wave 계획 작성
Agent 1
  • 11 steps: input 파싱 → 코드 탐색 → 사이드이펙트 분석 → 분기 매트릭스 → Wave 분할
  • 복잡도 분류 (LOW/MEDIUM/HIGH) → MEDIUM 이상은 static_quality_constraints 추가
  • TDAD: 실패하는 테스트를 먼저 작성 (버그수정·새기능·리팩토링)
  • 고위험 모듈 플래그 (공유 훅·전역 스토어·API 클라이언트)
  • 출력: .claude/plans/<task>.md (R1~R11)
2
implementer (Sonnet S2 long-lived)
Wave 단위 코드 작성 · Pre-constraint injection · 보호 파일 편집 금지
Agent 2
  • Pre-implementation Constraint Injection: 코드 작성 전 구조 제약 내재화 (함수 ≤20줄, 중첩 ≤3단계 등)
  • Wave 단위 진행 + checkpoint commit (plan R11 기준)
  • TDAD 테스트를 통과시키는 것이 완료 정의
  • 보호 파일 편집 시 즉시 중단 + 사용자 보고
  • functional-qa fail 시 같은 세션으로 재진입 (S2 long-lived)
3
functional-qa (Haiku)
6개 게이트 정적 검증 · 영향 반경 탐색 · 매 wave 후 실행
Agent 3
  • Gate 1: Lint (project_type별 자동 명령 선택)
  • Gate 2: Type Check (tsc / mypy / go vet / cargo check)
  • Gate 3: Pattern Check (금지 패턴 grep + 커스텀 패턴)
  • Gate 4: TDAD Test (planner가 작성한 실패 테스트 통과 확인)
  • Gate 5: Static Complexity (함수 길이·중첩 깊이·파라미터 수)
  • Gate 6: Impact Radius (importer 탐색 + 무한호출·캐시충돌·인터셉터 중복 감지)
4
design-qa (조건부)
Figma 4축 검증 — 토큰·매핑·접근성·반응형
Agent 4
  • plan에 Figma URL(R3)이 있을 때만 실행 (없으면 skip)
  • A축: 디자인 토큰 정확 매칭 (자동 fix)
  • B축: 컴포넌트 매핑 검증
  • C축: 접근성 (aria, contrast ratio)
  • D축: 반응형 브레이크포인트
5
visual-qa (조건부)
Storybook / Playwright 스냅샷 회귀 검증
Agent 5
  • 도구 자동 감지: Storybook → Playwright → jest-snapshot → pytest-screenshot
  • design-qa가 skip이면 함께 skip
  • 픽셀 diff 임계값 초과 시 fail → implementer 재진입
6
tracking-implementer (조건부)
TRACK 주석 마커를 실제 트래커 호출로 치환
Agent 6
  • plan R8 (트래킹 계획)이 있을 때만 실행
  • 외부 SDK 직접 호출 금지 — 프로젝트 기존 래퍼 함수 탐색 후 사용
  • 래퍼 없으면 TODO 주석으로 대체
7
tracking-qa (조건부)
외부 SDK 신규 호출 0 · 미번역 TRACK 마커 · 회귀 검증
Agent 7
  • tracking-implementer가 skip이면 함께 skip
  • 새로운 외부 SDK import 0건 강제
  • TRACK 주석 마커 미치환 = fail
8
release
Draft PR 생성 · 보호 브랜치 검증 · 자기강화 신호 추출
Agent 8
  • 베이스 브랜치 자동 감지: develop → alpha → beta → staging → dev
  • main / master / prd / production 타겟 영구 금지
  • 항상 Draft PR로 생성 (human review 보장)
  • QA 실패 패턴 → project-patterns.md 자기강화 등록

QA 게이트 (6단계)

모든 wave가 완료된 후 6개 게이트를 순서대로 통과해야 합니다. 어느 게이트라도 fail이면 implementer가 재진입합니다.

1

Lint

project_type에 따라 자동으로 lint 명령 선택. ESLint / ruff / golangci-lint / cargo clippy 등

Hard fail
2

Type Check

tsc --noEmit · mypy · go vet · cargo check · mvn compile

Hard fail
3

Pattern Check

console.log · 직접 axios import · wildcard import · naked panic 등 공통 금지 패턴 + 프로젝트 커스텀 패턴

Hard fail
4

TDAD Test

planner가 구현 전에 작성한 실패 테스트를 통과시켜야 완료. 버그수정·새기능·리팩토링에 필수.

Hard fail
5

Static Complexity

함수 ≤20줄 · 중첩 ≤3단계 · 파라미터 ≤3개. MEDIUM/HIGH 복잡도 태스크에만 적용. (LOW = skip)

Hard fail
6

Impact Radius QA

변경 파일을 import하는 모든 파일 자동 탐색. 무한 호출·캐시 키 충돌·인터셉터 중복·조건부 훅 호출을 탐지.

Hard fail

코드 품질 보장 (98점 목표)

📊

연구 근거: 순환복잡도와 코드 스멜 수의 Spearman 상관계수 ρ=0.94. OOP/복잡 태스크에서 스멜이 불균형 증가 (평균 +63%, OOP 주제 +138%). Pass@1과 정적 분석 점수는 상관없음 — 별도 게이트 필수.

두 가지 핵심 전략

1. Pre-implementation Constraint Injection

implementer가 코드를 한 줄도 쓰기 전에 구조적 제약을 시스템 규칙으로 내재화합니다. 사후 교정이 아닌 사전 차단으로 위반을 근본적으로 방지합니다.

HARD LIMITS (구현 전 내재화)
  ┌─────────────────────────────────────────────────────────┐
  │ 함수/메서드 ≤ 20줄   →  초과 즉시 helper 함수로 추출  │
  │ 중첩 깊이 ≤ 3단계   →  guard clause 패턴 사용         │
  │ 파라미터 ≤ 3개      →  초과 시 options 객체로 묶기    │
  │ JSX ≥ 20줄          →  서브 컴포넌트로 추출            │
  │ console.log 금지    →  logger 또는 제거                │
  └─────────────────────────────────────────────────────────┘

2. TDAD (Test-Driven AI Development)

planner가 구현 전 실패하는 테스트를 먼저 작성합니다. implementer는 이 테스트를 통과시키는 것이 완료 정의입니다.

작업 유형TDAD비고
버그 수정● 필수재현 테스트 = 명세
새 기능● 필수모든 분기 케이스 강제
리팩토링● 필수동작 보존 safety net
성능 최적화● 필수회귀 방지
디자인 변경● 조건부분기 처리 변경 시만
워딩 수정○ 스킵—
문서/인프라○ 스킵—

Impact Radius QA

변경된 파일만 검증하면 충분하지 않습니다. SWR 훅, 전역 스토어, API 클라이언트처럼 여러 파일에서 공유하는 모듈을 수정하면 직접 수정한 파일은 테스트를 통과해도 import하는 다른 파일에서 버그가 발생할 수 있습니다.

🔴

실제 사례: SWR 훅에서 캐시 키를 인라인 객체 {`{ id }`}로 넘기면 매 렌더마다 새 참조가 생성되어 무한 호출이 발생합니다. 훅 파일의 테스트는 통과하지만 이 훅을 사용하는 컴포넌트에서 문제가 터집니다.

자동 탐지 항목

🔁

무한 호출 (Hard fail)

SWR/React Query 캐시 키에 인라인 객체·배열 → 매 렌더 새 참조 생성

⚠️

조건부 훅 호출 (Hard fail)

if (cond) useHook() — Rules of Hooks 위반 패턴 자동 감지

🔗

인터셉터 중복 등록 (Hard fail)

API 클라이언트에 interceptors.use 2회 이상 감지

🔄

의존성 배열 누락 (Hard fail)

useEffect/useMemo/useCallback에 의존성 배열 없음

📦

selector 객체 반환 (Warning)

Zustand/Redux selector가 매 호출마다 새 객체 반환 → 불필요한 리렌더

📡

영향 반경 10개 초과 (Warning)

importer 10개 이상 → 사용자에게 경고 + 계속 진행

훅 & 가드레일

7개의 셸 훅이 Claude Code 이벤트에 반응해 자동으로 작동합니다.

훅 파일트리거역할

harness-pre-bash-guard.sh Bash 실행 전 보호 브랜치 push 차단, --force 차단, .env 커밋 차단, node_modules 편집 차단
harness-pre-impact-check.sh Edit 실행 전 보호 파일 편집 시 승인 요청, 공유 모듈 편집 시 importer 수 경고

harness-session-stop.sh 세션 종료 QA 실패 패턴 추출 → project-patterns.md 자기강화 신호

CLAUDE.md 생성

AI-Harness는 설치된 프로젝트의 실제 구조를 분석해 레이어별 CLAUDE.md를 자동 생성합니다. 에이전트들이 이 파일을 참조해 프로젝트 고유 패턴을 따릅니다.

Claude Code
/harness-init-claude-md

생성 예시

your-project/
├── CLAUDE.md ← 루트: 전체 TL;DR + 진입 규칙
├── src/
│ ├── components/CLAUDE.md ← 컴포넌트 패턴 + 금지 패턴
│ ├── hooks/CLAUDE.md ← 훅 작성 규칙 + 의존성 배열 주의사항
│ ├── services/CLAUDE.md ← API 호출 래퍼 패턴
│ ├── lib/CLAUDE.md ← 유틸리티 패턴
│ └── store/CLAUDE.md ← 전역 상태 패턴
└── .claude/
└── rules/project-patterns.md ← 금지 패턴 등록
⚠️

기존 CLAUDE.md는 덮어쓰지 않습니다. 스켈레톤(TODO 포함)만 AI로 보강합니다. 강제 재생성이 필요하면 --force 옵션을 사용하세요.

트러블슈팅

/implement 명령이 자동완성에 안 나옴

Claude Code는 스킬을 세션 시작 시 스캔합니다. Claude Code를 완전히 재시작하세요.

에이전트가 호출 안 됨

.claude/agents/*.md의 frontmatter name 필드가 파일명과 일치하는지 확인하세요.

---
name: functional-qa   # 파일명: functional-qa.md
---

hooks가 작동 안 함

  • chmod +x .claude/hooks/*.sh 실행 여부 확인
  • settings.local.json에 hooks 블록 존재 여부 확인
  • Claude Code 디버그 모드에서 stderr 출력 확인

Gate 6 (Impact Radius) 오탐

grep 기반 간이 탐지라 false positive가 발생할 수 있습니다. .claude/rules/project-patterns.md의 ## EXCLUDED 섹션에 제외 패턴을 등록하세요.

백업 디렉토리 정리

rm -rf .claude/_backup_*   # 확인 후 삭제
✅

문제 해결이 안 되면 --uninstall 후 재설치를 시도하세요. 기존 코드 파일은 건드리지 않습니다.
